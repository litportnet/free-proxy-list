# Schema

This document is the canonical reference for every file under `proxies/` on the `live` branch
(and the daily snapshot of the same tree on `main`). It is generated by
[`scripts/build.mjs`](scripts/build.mjs) from [`scripts/lib.mjs`](scripts/lib.mjs); see that file
for the source of truth if this document and the data ever disagree.

## Proxy object fields

Every `.json`/`.csv` row has exactly these fields, in this order:

| Field | Type | Null? | Meaning |
|---|---|---|---|
| `protocol` | string | never | One of `http`, `socks4`, `socks5` |
| `ip` | string | never | Dotted-quad public IPv4 address to connect to |
| `port` | integer | never | 1–65535 |
| `url` | string | never | `protocol://ip:port` |
| `anonymity` | string | never | `transparent` (leaks your real IP to the target), `anonymous` (no leak, but a proxy header like `Via`/`X-Forwarded-For` is present), `elite` (neither), or `unknown` (the judge returned no headers block to check) |
| `https` | boolean | yes | `true` when this HTTP proxy successfully tunnelled an HTTPS request via `CONNECT` with the origin TLS certificate intact; `false` when it was tried and failed; `null` when not yet measured. This is *not* whether the proxy itself speaks TLS |
| `latency_ms` | integer | never | Round-trip time of the last successful check, milliseconds |
| `latency_median_ms` | number | yes | Median of the recent successful-check latency window, milliseconds; `null` when the window is unavailable |
| `uptime_24h` | number | never | Percentage of checks that succeeded in the trailing 24 hours, one decimal place |
| `uptime_7d` | number | yes | Percentage of checks that succeeded in the trailing 7 days, one decimal place. `null` when `checks_7d < 50` — not enough history to be meaningful |
| `checks_7d` | integer | never | Number of checks `uptime_7d` is computed from |
| `exit_ip` | string | yes | The IP address the judge observed making the request. Usually equal to `ip`; differs behind NAT/rotating gateways. `null` when the last successful check did not return one |
| `exit_shared` | integer | never | How many proxies in *this* snapshot share the same `exit_ip`. `1` means unique. Proxies with `exit_ip: null` are always reported as `1` |
| `country` | string | yes | Lowercase ISO 3166-1 alpha-2 code of the exit IP's location |
| `region` | string | yes | Geolocated region/state name |
| `city` | string | yes | Geolocated city name |
| `timezone` | string | yes | IANA timezone name, e.g. `America/Los_Angeles` |
| `asn` | integer | yes | Autonomous system number of the exit IP (the numeric part of e.g. `AS13335`) |
| `asn_org` | string | yes | Organisation name registered to that ASN |
| `sources_count` | integer | never | Number of independent proxy lists this candidate was seen on before being added |
| `first_seen` | string | never | ISO 8601 UTC timestamp of when this proxy was first added |
| `last_checked` | string | never | ISO 8601 UTC timestamp of the last check that produced this row |

CSV files use the same field names as a header row, in the same order, with
[RFC 4180](https://www.rfc-editor.org/rfc/rfc4180) quoting. JSON files are a plain array of these
objects, 2-space indented, UTF-8, `\n` line endings. `.txt` files hold one value per line and no
trailing blank line beyond the final newline.

## File semantics

| Path | `.txt` contents | Included when |
|---|---|---|
| `proxies/all.{txt,json,csv}` | `url` per line | Passed the publish gate (below) |
| `proxies/http.{txt,json,csv}` / `socks4` / `socks5` | `ip:port` per line | `protocol` matches |
| `proxies/https.{txt,json,csv}` | `ip:port` per line | `https === true`. Always present, even when empty |
| `proxies/fast.{txt,json,csv}` | `url` per line | `latency_ms < 1000` |
| `proxies/stable.{txt,json,csv}` | `url` per line | `uptime_7d >= 90` and `uptime_7d` is not null (which also requires `checks_7d >= 50`) |
| `proxies/anonymous.{txt,json,csv}` | `url` per line | `anonymity` is `anonymous` or `elite` |
| `proxies/countries/<cc>/all.{txt,json,csv}` | `url` per line | `country === <cc>`, lowercase ISO-2 |
| `proxies/countries/<cc>/{http,socks4,socks5}.{txt,json,csv}` | `ip:port` per line | `country === <cc>` and `protocol` matches |
| `proxies/stats.json` | — | Always present; see below |
| `proxies/badges/*.json` | — | [shields.io endpoint schema](https://shields.io/badges/endpoint-badge) |

A missing file under `proxies/countries/` (or `proxies/https.*` being empty) means "no proxies of
that kind right now" — not an error. Only non-empty country/protocol combinations get a file.

## `stats.json`

```json
{
  "generated_at": "2026-09-09T18:00:00.000Z",
  "expires_at": "2026-09-09T18:10:00.000Z",
  "interval_sec": 300,
  "max_age_min": 30,
  "totals": { "all": 0, "http": 0, "socks4": 0, "socks5": 0, "https": 0, "fast": 0, "stable": 0, "anonymous": 0 },
  "by_anonymity": { "transparent": 0, "anonymous": 0, "elite": 0, "unknown": 0 },
  "countries": { "us": 0 },
  "countries_count": 0,
  "verification": { "...": "see README `How we check`" },
  "source_api": "https://litport.net/api/free-proxy",
  "site": "https://litport.net/free-proxy"
}
```

`expires_at` is `generated_at + 2 * interval_sec`. If it is in the past, the publish job has
stopped running or is failing — `badges/status.json` and `.github/workflows/stale-check.yml`
exist to surface exactly that.

## Sort order

Every list is sorted `uptime_7d` descending (proxies with no `uptime_7d` sort last), then
`latency_ms` ascending, then `url` ascending as a final tie-breaker. This makes the sort fully
deterministic and means `head -1` (or `head -n 20`) on any `.txt` file is always a meaningful
"best proxies first" sample.

## URL stability promise

File paths under `proxies/` on the `live` branch are stable. New files may be added at any time
without notice (for example a new protocol or a new slice). Any removal of an existing path will
be announced in this file at least 30 days ahead of the change.
